侧边栏竞品结论

侧边栏体现产品围绕什么对象工作。超节点应以模型业务组织用户端，以算力供给、运行保障和治理组织管理端，再用项目范围和对象关联连接各项功能。

结论竞品实际情况超节点的架构取舍
核心管理对象决定一级目录百舸组织开发机、分布式训练、在线服务；Run:ai（算力调度平台）分列工作负载、项目、节点；AHR（自主硬件恢复）分列资源、告警、运维流程与审计。分别侧重模型交付、资源分配和异常处置。用户端以模型业务组织工作域；管理端以算力供给、运行保障和治理组织工作域。按职责选择核心对象，避免直接拼接几类竞品的目录。
工作范围、复用资产与业务任务分层组织Run:ai（算力调度平台）用项目管理额度、用工作负载管理执行；百舸将数据集、模型与开发训练入口分开；灵犀Base（基础组件）按系统和租户划定资源范围。项目限定工作范围；数据、模型、镜像保留稳定管理入口；开发、训练、推理分别管理实例、任务与服务。在对象详情发起下一步，复用已有输入，减少重复配置。
专业模块保留职责边界，页面贯通业务上下文CCAE（集群运维管理平台）资源视图按计算、网络、存储等对象分层；AHR（自主硬件恢复）将告警与运维流程分开；灵犀Base（基础组件）区分系统管理员和租户职责。专业对象和处理权限各有归属。资源、运行处置、安全、审计各有管理入口；任务、资源、事件相互可查。跨模块沿用对象和时间，跨角色传递处理请求及结果，避免同一对象在多处重复管理。

用户端组织：项目范围 ｜ 复用资产（数据、模型、镜像）｜ 业务执行（开发、训练、推理）｜ 用量与费用。

管理端组织：算力供给（设备、集群、资源池、队列）｜ 运行保障（监控、告警、恢复）｜ 治理（安全、审计）｜ 运营（按需启用）。

这是工作域与功能归属的框架，具体菜单范围以MRD（市场需求文档）为准；工作台提供快捷入口，项目管理保留成员与额度等管理动作。AIStation（人工智能开发平台）普通用户手册仅作层级参照；AD-AIDC（智算基础设施管理平台）功能线索与完整左栏分开取证；角色分工不代表竞品均采用独立双端。

05 · 角色分工清晰，跨端交接不断链

高优先级建议
竞品证据 / 观察

百度百舸按资源、训推任务组织功能；H3C（新华三） 灵犀明确区分系统管理员与租户职责。竞品存在角色权限差异，但不能由此推断均具有独立 Portal（用户门户） / Admin（管理端），跨角色交接能力也需要额外核验。

交互设计判断

两端导航应遵循角色的任务与职责，而不是把同一菜单机械拆开；用户遇到异常时需要明确责任归属、可见处理进度，并在处理完成后回到原任务。

超节点机会点
Portal（用户门户） 聚焦任务使用与异常反馈；Admin（管理端） 聚焦资源配置与问题处理。以关联的任务、资源和事件对象传递上下文，支持负责人、处理进度与恢复结果反馈。
对应页面 / 设计对象

Portal（用户门户） 首页 / 任务详情 / 异常提示；Admin（管理端） 资源与权限管理 / 告警详情 / 处理队列 / 通知

06 · 跨模块不必消失，但上下文不能丢

中优先级建议
竞品证据 / 观察

各产品分别强调训推任务、算力调度和运维恢复，导航组织重心各异。

交互设计判断

“统一入口”不是把所有功能塞在一个界面；更重要的是用户完成关键任务时不丢失对象、状态和返回路径。

超节点机会点
建立任务、资源、事件三类可互相定位的对象链接，统一状态语义和返回路径。
