MRD v0.5 范围与差异说明

阶段 03 的“组织与资源准备”为业务阶段名称，MRD 中“租户管理”等功能名称不变。安全管理员负责成员与授权，系统管理员负责技术资源，运营管理员协作配额；“系统调度”为系统动作，不是用户角色。

阶段 07：资源与 Token 计量、账单管理已列入 MRD（OM-005/006）；费用分析、北向 API 已列入需求（OM-007/020），第三方消纳转售另属演进范围（OM-021）。Token 消费者为应用凭据主体，平台计量及审计到 Key/租户粒度。

阶段 08：调度策略管理依据 SCH-021；资源优化画像与仿真（SCH-024/025）、多集群管理（SCH-046～054）及容量规划（DCIM-055）属于 MRD 后续演进范围。原“新增资源”改为扩展规划，不代表已执行扩容；MRD 规划结果不等于功能已上线。

04 · ROLE & RESPONSIBILITY

全链路角色参与与协作关系

各场景由对应角色承担主责，其他角色按职责参与协作。系统管理、安全管理与审计职责相互分离，交付和现场维护作为外部协作参与。

注：SC-1 的交付方属于业务流程中的外部协作方，并非新增的 Admin 角色；SC-4 的现场硬件维护同理。Token 消费者是凭据主体，平台对 API Key / 租户级别负责，不管理第三方应用的终端用户。安全管理员负责授权；安全审计员独立且只读，不参与审批、修改或删除审计日志。
